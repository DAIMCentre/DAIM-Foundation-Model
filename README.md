# daim-foundation-models

[![tests](https://github.com/DAIMCentre/DAIM-Foundation-Model/actions/workflows/tests.yml/badge.svg)](https://github.com/DAIMCentre/DAIM-Foundation-Model/actions/workflows/tests.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)

Readable, CPU-first examples for studying how predictive models are built and
evaluated. The repository contains two connected paths:

1. a last-value time-series baseline that introduces temporal evaluation; and
2. a decoder-only language model built directly from PyTorch primitives and
   trained from random initialisation.

The language-model example uses no pretrained weights, hosted model, trainer
framework or `torch.nn.Transformer`.

## Requirements and installation

- Python 3.10 or later
- a CPU; no GPU or API key is required

```bash
python3.11 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
python -m pip install -e ".[test]"
```

## Path 0: time-series baseline

```bash
python examples/run_simple_baseline.py --output-dir results/example
```

The example creates a deterministic trend-and-seasonality series, holds out its
final twelve points, repeats the last observed value as the forecast, and writes
`experiment.yaml`, `metrics.json` and `forecast.csv`.

This baseline has no learned parameters. It exists so later trainable models
can be compared with a transparent reference under the same temporal split and
metrics.

## Path 1: language model from scratch

The initial training corpus is a small, deterministic subset of the official
TinyStories V2 GPT-4 train and validation files. TinyStories is synthetic; its
dataset card lists the licence as CDLA-Sharing-1.0.

Prepare the default 1,000/100-story subsets once:

```bash
python scripts/prepare_tinystories.py
```

The preparation script uses HTTP byte ranges, retains complete
`<|endoftext|>`-delimited stories, and writes:

```text
data/tinystories_v2/train.txt
data/tinystories_v2/valid.txt
data/tinystories_v2/manifest.yaml
```

The manifest records the official URLs, selection rule, licence, story counts,
file sizes and SHA-256 checksums. Training validates these checksums and never
downloads data implicitly. The `data/` directory is ignored by Git.

Train the 2,732,928-parameter `tiny` model:

```bash
python examples/run_lm_from_scratch.py \
  --steps 50 \
  --output-dir results/lm-example
```

The command writes:

- `run.yaml`: resolved configuration, seed, versions and data checksums;
- `metrics.jsonl`: step-level training and validation losses;
- `sample.txt`: the prompt and generated bytes decoded as UTF-8;
- `checkpoint.pt`: only when `--save-checkpoint` is supplied.

To use controlled local text instead of the prepared dataset, provide both
files explicitly:

```bash
python examples/run_lm_from_scratch.py \
  --train-data tests/fixtures/micro_corpus.txt \
  --valid-data tests/fixtures/micro_corpus.txt \
  --steps 2 --batch-size 2
```

Inspect the untrained 97,949,184-parameter configuration without allocating its
weights:

```bash
python examples/inspect_100m_model.py
```

This uses PyTorch's `meta` device. The command does not train the model and does
not imply that it has learned language capability.

## What the model executes

```text
UTF-8 text
  -> byte token IDs
  -> shifted input/target windows
  -> token and position embeddings
  -> causal self-attention + MLP blocks
  -> next-byte logits
  -> cross-entropy loss
  -> AdamW parameter updates
  -> autoregressive generation
```

The tokenizer intentionally has only 256 byte values. It is transparent and
reversible, but it is not proposed as an adequate research tokenizer for a
0.1B-parameter model.

## Supported Python interface

```python
from daim_fm import (
    ByteTokenizer,
    LMConfig,
    TrainingConfig,
    TransformerLM,
    generate,
    get_preset,
    train_language_model,
)
```

The original `generate_synthetic_series`, `split_series`,
`last_value_forecast`, `mae` and `rmse` interfaces remain supported.

## Tests

```bash
python -m pytest -q
```

Tests use the small original file in `tests/fixtures/`; they do not access the
network or run a 0.1B forward pass.

## Repository layout

```text
examples/   runnable forecasting, training and inspection examples
scripts/    explicit TinyStories preparation
src/        importable model, training and baseline code
tests/      offline unit and end-to-end tests
results/    generated run records
```

All included runs are demonstrations of mechanics and reproducibility, not
scientific findings about foundation-model performance.
